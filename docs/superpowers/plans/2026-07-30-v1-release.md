# v1.0.0 Version Label and GitHub Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Display `版本v1.0.0` in the main window, document the portable Windows download, rebuild the privacy-safe ZIP, and publish it as Release `v1.0.0` in the existing GitHub repository.

**Architecture:** Add one centralized version constant and a permanent `QLabel` in the existing status bar, protected by the current UI smoke test. Keep binaries out of Git history: source and README go to `main`, while the rebuilt ZIP is uploaded as a GitHub Release asset.

**Tech Stack:** Python 3.13, PySide6, pytest-qt, PyInstaller 6.21, PowerShell ZIP tooling, Git, GitHub CLI.

## Global Constraints

- The visible text must be exactly `版本v1.0.0`.
- The label must remain visible while temporary status messages are shown.
- The release targets Windows 10/11 64-bit and requires no Python installation.
- User data remains under `%APPDATA%\PersonalTools\AutumnRecruitmentLedger\`.
- The ZIP must not contain databases, logs, backups, source, tests, or build intermediates.
- Publish to `wangtianyu-0403/autumn-recruitment-ledger`; do not create another repository.
- Publish the ZIP as the ASCII-named Release asset `autumn-recruitment-ledger-Windows-x64.zip`, not as a Git-tracked binary.
