# v1.1.3 UI Bug Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix post-drag blank table rows and prevent accidental status changes from mouse-wheel scrolling, then publish v1.1.3.

**Architecture:** Keep reorder persistence synchronous but defer the post-drop table rebuild through a window-owned single-shot `QTimer`, so Qt finishes native MoveAction cleanup before new items and widgets are installed. Introduce a focused `StatusComboBox` that ignores wheel events while closed, allowing the enclosing table to scroll, while preserving explicit popup selection.

**Tech Stack:** Python 3.10+, PySide6, SQLite, pytest, pytest-qt, PyInstaller, PowerShell, Git, GitHub CLI.

## Global Constraints

- Product name remains `招聘记录台账`.
- Version changes from `1.1.2` to `1.1.3`.
- Database filename remains `autumn_recruitment.db`; no schema migration is added.
- Drag reorder stays transactionally persisted through the existing service/repository APIs.
- Mouse-wheel input over a closed row-status combo must never change business state.
- Opening the status popup explicitly must preserve normal browsing and selection.
- Do not edit, delete, restore, export, or reorder real user records during verification.
- Release asset name remains `Recruitment-Record-Ledger-Windows-x64.zip`.

    qtbot, monkeypatch, tmp_path, service, app_paths, database

    _isolated_settings(monkeypatch, tmp_path)
    first = _create_record(service, "甲公司", "2026-01-01")
    second = _create_record(service, "乙公司", "2026-01-02")
    window = MainWindow(service, BackupManager(database, app_paths), app_paths)

    window.sort_mode_combo.setCurrentIndex(
        window.sort_mode_combo.findData(SortMode.MANUAL.value)

    assert window.table.cellWidget(0, 6) is not None
