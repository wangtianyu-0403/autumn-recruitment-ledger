# 公司记录拖动排序与置顶设计

## 目标

为“招聘记录台账”增加持久化的公司记录顺序管理。用户可以拖动公司记录调整顺序、
置顶或取消置顶，并可选择按投递时间或最后更新时间排序。排序信息随数据库备份、
恢复和迁移保留。

## 方案选择

采用在现有 `applications` 表中保存排序元数据的方案：

- `is_pinned INTEGER NOT NULL DEFAULT 0`
- `manual_order INTEGER NOT NULL`

该方案比本机配置持久化更适合台账数据：备份数据库即会备份顺序，也不需要维护一张
容易与记录失去同步的独立排序表。本机配置仅保存最后使用的排序模式。

数据库 schema 版本递增。升级已有数据库时，为所有现有记录填充确定且唯一的
`manual_order`：按照升级前的默认顺序
`updated_at DESC, id DESC`
依次编号，使用户首次打开新版时看到的顺序不发生突变。

## 排序模式

工具栏增加排序选择框，提供：

1. `手动排序`
2. `按投递时间`
3. `按最后更新时间`

两种时间模式均为最新时间在前；相同时间使用 `manual_order`，最后使用 `id` 作为
稳定兜底顺序。所有模式首先按 `is_pinned DESC` 分组，保证置顶记录始终显示在普通
记录之前。

当前排序模式保存在当前 Windows 用户的本机应用设置中，下次启动沿用。首次使用
v1.1.2 时默认选择“按最后更新时间”，与旧版行为一致。

## 手动拖动

表格支持整行拖动，并以记录 ID 而不是行号识别记录，避免刷新、筛选或排序后操作
错误对象。

拖动规则：

- 在“手动排序”中，拖放完成后立即在一个数据库事务内重新编号并刷新表格。
- 在时间排序模式开始拖动时，先将当前完整排序快照写为手动顺序，自动切换到
  “手动排序”，再完成本次移动。
- 置顶组和普通组分别排序。拖动不能隐式改变置顶状态；跨越分组边界的放置会落在
  原分组最接近边界的位置。置顶状态只能通过明确的“置顶/取消置顶”操作改变。
- 搜索或状态筛选生效时，只改变当前可见记录之间的相对顺序。隐藏记录保留原位置
  槽位，从而避免一次局部拖动打乱整个列表。
- 拖动失败时恢复刷新前的数据库顺序，并显示错误提示。

每次重新编号使用固定间隔或连续整数均可，但结果必须唯一、确定，并在单个事务中
完成。编辑记录不得改变 `manual_order`；软删除和恢复保留原手动位置。

新建普通记录插入普通组顶部。新建记录默认不置顶。记录取消置顶后进入普通组顶部；
记录被置顶后进入置顶组顶部。后续可继续拖动调整。

## 置顶交互

每行操作区增加一个文字操作：

- 普通记录显示“置顶”。
- 已置顶记录显示“取消置顶”。

执行后立即持久化并刷新当前列表。置顶行在公司名称旁显示简洁的置顶标记，便于
识别，但不新增占用大量空间的表格列。

置顶不修改 `updated_at`，因为它是显示顺序设置，不是招聘进展内容更新。按最后
更新时间排序时，不会因为置顶操作而伪造业务更新时间。

## 组件边界与数据流

### 数据库层

负责 schema 升级、字段默认值和索引。新增覆盖
`is_deleted`、`is_pinned` 及排序字段的索引，以支持常用列表查询。

### Repository 层

列表接口接收明确的排序模式，并生成白名单限定的 `ORDER BY`，不接受任意 SQL
字段。新增事务化接口：

- 设置或取消置顶；
- 保存一组记录的新手动顺序；
- 在自动排序切换为手动排序时保存完整顺序快照。

### Service 层

校验记录 ID 是否存在、是否重复，以及可见重排集合是否合法。它负责将筛选结果的
相对移动合并回完整顺序，不让 UI 直接操作 SQL。

### UI 层

排序选择框管理模式选择；专用表格组件负责拖放并发出记录 ID 顺序；主窗口调用
Service、显示错误并刷新。现有搜索、状态筛选、统计卡片、编辑、历史、删除、导出
和回收站功能继续使用原有职责边界。

数据流为：

`用户拖放或置顶 → UI 提交记录 ID → Service 校验/合并 → Repository 事务写入 → UI 刷新`

## 搜索、筛选和导出

搜索和状态筛选继续先限制记录集合，再应用置顶及当前排序模式。清除筛选后完整列表
保持一致的手动顺序。

CSV 导出继续导出当前搜索和状态筛选结果，并使用屏幕当前排序顺序；新增排序字段
不作为业务列导出。

回收站不提供拖动或置顶操作。恢复记录后保留删除前的 `is_pinned` 和
`manual_order`。

## 错误处理

- 数据库升级在事务中执行；任何字段创建或回填失败都回滚，不留下半升级状态。
- 重排请求包含不存在、重复或跨越非法集合的 ID 时拒绝整次操作。
- UI 在保存失败时显示提示并从数据库重新加载，不能只保留视觉上的错误顺序。
- 本机排序模式配置损坏或值未知时回退到“按最后更新时间”。

## 验收与测试

至少覆盖以下测试：

- 旧 schema 升级后新增字段存在，旧记录顺序与升级前一致。
- 重复初始化不会重复迁移或改变手动顺序。
- 三种排序模式均稳定，时间相同时结果确定。
- 置顶记录在所有排序模式下均位于普通记录之前。
- 置顶、取消置顶和手动顺序在程序重启后保留。
- 编辑记录不改变手动顺序，但按最后更新时间排序会反映新的更新时间。
- 自动排序模式首次拖动会切换为手动模式并保留拖动前的完整排序快照。
- 筛选结果内拖动只改变可见记录相对顺序，隐藏记录位置不被意外打乱。
- 拖动不能隐式置顶或取消置顶。
- 新建、软删除、恢复记录符合规定的位置行为。
- CSV 按屏幕顺序导出且不包含内部排序字段。
- Repository 拒绝未知排序模式和无效重排 ID。
- UI 包含排序选择框、置顶操作和可拖动表格，原有操作按钮仍可用。
- 完整自动化测试、代码编译检查、Windows 构建和便携包启动检查通过。
