# v1.1.3 拖动显示与状态滚轮修复设计

## 目标

修复“招聘记录台账”中的两个界面缺陷，并发布 v1.1.3：

1. 手动排序拖动记录后，不再出现另一行只剩浅蓝背景和部分控件、文字消失的情况。
2. 鼠标滚轮经过表格“当前进度”下拉框时，不再意外修改投递状态；表格仍能正常滚动。

## 已确认的根因

### 拖动后文字消失

`ApplicationTableWidget.dropEvent()` 在 Qt 原生拖放事务尚未完全结束时同步发出
`rows_reordered`。`MainWindow._rows_reordered()` 随即保存顺序并同步重建表格。事件返回后，
Qt 仍按原生 MoveAction 清理拖动源单元格，因而清除了刚重建的文字项。状态下拉框和按钮是
cell widget，生命周期与 `QTableWidgetItem` 不同，所以可能继续显示。数据库记录和顺序没有
丢失；切换排序模式触发下一次完整刷新后，文字会恢复。

### 滚轮意外改变状态

表格每行的“当前进度”使用普通 `QComboBox`。Qt 默认会让关闭状态下、鼠标指针所在的
`QComboBox` 响应滚轮并改变当前选项，继而触发 `currentTextChanged` 和数据库状态更新。

## 方案选择

采用以下组合方案：

- 顺序持久化保持同步，保证拖动失败能立即提示；表格视觉重建通过 `QTimer.singleShot(0, ...)`
  延迟到 Qt 完成原生拖放清理后的下一轮事件循环。
- 新增仅用于表格状态列的滚轮安全下拉框。下拉列表关闭时忽略滚轮事件，并把事件继续交给
  父级滚动区域；用户主动打开下拉列表后，列表仍可用滚轮浏览并正常点击选择。

不采用“把成功拖放伪装成失败”方案，因为这依赖不同 Qt 版本对 drop action 的处理细节，
也可能产生错误的拖动反馈。不重写为 Model/View 架构，因为对两个局部缺陷而言范围和风险
过大。

## 组件与数据流

### 拖动排序

1. `ApplicationTableWidget` 计算新的 application ID 顺序并发出 `rows_reordered`。
2. `MainWindow._rows_reordered()` 立即调用 `ApplicationService.reorder_visible()`。
3. 保存成功时，自动排序模式仍无重复保存地切换为手动排序。
4. `MainWindow` 将 `refresh_data()` 排入下一轮 Qt 事件循环，届时原生拖放清理已结束。
5. 刷新从数据库重新读取记录，并完整重建文字项和 cell widgets。
6. 保存失败时显示中文错误，并同样排队刷新，以数据库顺序恢复界面。

为避免在同一事件循环中重复排队刷新，主窗口维护一个轻量的“刷新已排队”状态；重复请求
合并为一次刷新。普通搜索、筛选、排序按钮触发的刷新仍保持原有同步语义。

### 状态滚轮保护

新增 `StatusComboBox(QComboBox)`：

- 下拉列表关闭时，`wheelEvent()` 调用 `event.ignore()`，不改变当前选项；事件可继续传播给
  表格滚动区域。
- 下拉列表打开时，滚轮由弹出的列表视图处理，可浏览选项。
- 键盘、鼠标点击、状态颜色、`currentTextChanged` 保存和失败回滚逻辑保持不变。
- 仅表格“当前进度”使用该控件；工具栏筛选和排序控件不改变行为。

## 错误处理与兼容性

- 数据库 schema、排序字段和业务记录不变，不需要数据迁移。
- 拖动持久化仍使用 v1.1.2 已验证的单事务接口。
- 排队刷新执行前若窗口已关闭，Qt 的对象生命周期会自动取消绑定到已销毁接收者的调用；
  实现不捕获悬空窗口引用。
- 版本从 `1.1.2` 更新为 `1.1.3`，更新资产名称保持
  `Recruitment-Record-Ledger-Windows-x64.zip`。
